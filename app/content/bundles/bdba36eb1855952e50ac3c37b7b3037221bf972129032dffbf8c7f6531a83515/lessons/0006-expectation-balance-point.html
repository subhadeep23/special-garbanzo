Expectation — the Balance Point

One number that says where a distribution sits. ~20 min.

TODAY'S WIN  You'll be able to compute E[X] from a mass function or a density, read it as the point where the distribution balances, use E[aX + b] = aE[X] + b without thinking, and explain why E[X²] is not (E[X])².

0 · Spaced recall — no peeking

• X is uniform on (0, 1/3). What is its density, and is a density that size a problem?

• Three fair coins, X = number of heads. Write down its mass function.

Answers: the density is 3 on that stretch, and that's fine: only areas are probabilities (L5). And p(0), p(1), p(2), p(3) = 1/8, 3/8, 3/8, 1/8, the jump sizes of L4's staircase. Keep that list; you'll use it in a minute.

1 · The long-run average

A street game: roll a fair die, and you win as many rupees as the face shows. What is one roll worth?

Play it 600 times. Each face turns up about 100 times, so you collect about

100 × (1 + 2 + 3 + 4 + 5 + 6) = 2100 rupees,

or 3.5 rupees per roll. Notice where the 3.5 came from: every possible value, times the share of rolls it gets, added up. The share is just the probability, 1/6.

That weighted average has a name. The expectation of a discrete X (also called its expected value or mean, and written E[X] or μ) is

E[X] = Σ x · p(x)  over every value x that X can take.

Each value counts in proportion to how likely it is. For the die, and for your three coins:

E[X] = (1 + 2 + 3 + 4 + 5 + 6)/6 = 3.5

0(1/8) + 1(3/8) + 2(3/8) + 3(1/8) = 12/8 = 1.5 heads

The long run of real rolls settles on 3.5, and of real triple tosses on 1.5 heads.

Two things already stand out. You can't roll a 3.5, and you can't toss 1.5 heads. The expectation is a summary of the distribution, not a prediction of the next outcome. Nobody "expects" 3.5 on a die.

2 · Where the distribution balances

Now a picture that makes the formula feel inevitable. Treat each probability as a weight sitting on a beam at its value. Where must the fulcrum go so the beam stays level? Guess for the x/10 weights before you tap them, then slide the fulcrum yourself.

Why does the level point always equal Σ x p(x)? Each weight pulls with its size times its distance from the fulcrum: (x − t) p(x), positive on the right, negative on the left. Add the pulls:

Σ (x − t) p(x) = Σ x p(x) − t Σ p(x) = E[X] − t

because the weights add to 1. That is zero exactly when t = E[X]. The physics and the arithmetic say the same thing.

Say it in one line

The expectation is the balance point of the distribution: E[X] = Σ x p(x), the one place where the deviations cancel, Σ (x − μ) p(x) = 0.

A see-saw with children on it. Heavier children (more likely values) pull harder, and so do children sitting further out (values far from the fulcrum). The beam is level when the pulls cancel, and that spot is the mean. Try the "Both ends" weights: half at 1, half at 4. The balance is at 2.5, where no weight sits at all, exactly as a see-saw with two equal children balances in the empty middle.

Where it breaks: a real see-saw always has a balance point. A distribution whose weights reach out forever can pull so hard from far away that there is none: the density 1/(π(1 + x²)) has no mean, because Σ |x| p(x) (or ∫ |x| f(x) dx) is infinite. That's why the definition quietly requires that sum to be finite. Also, probability weights are never negative and always total exactly 1; real children are not so obliging.

3 · Sand on the beam: densities

For a continuous X the weight isn't in lumps; it's spread like sand, with density f(x) per unit length. Replace the sum by an integral:

E[X] = ∫ x f(x) dx  over the whole line, provided ∫ |x| f(x) dx is finite.

A uniform on (0, θ) has flat sand, so it balances in the middle: ∫0θ x (1/θ) dx = θ/2. The triangle from L5, peaked at 3, balances at 3 by symmetry. When the sand is lopsided, the balance shifts toward the heavy side, and the integral tells you how far.

4 · Functions of X: keep the weights, move the values

Often you need the average of some function of X: the square of a measurement, a cost, a reward. If X lands on x with chance p(x), then g(X) lands on g(x) with the same chance. So nothing new is needed:

E[g(X)] = Σ g(x) p(x)  or  ∫ g(x) f(x) dx

The weights stay where they were in probability; only their positions on the line move. Watch what that does to the balance point, and predict before the last step.

Straight-line functions are the easy case, and the most used rule in this chapter. For any numbers a and b,

E[aX + b] = a E[X] + b

Scaling every value by a scales the balance point by a; shifting every value by b shifts it by b. Together with its big brother, E[X + Y] = E[X] + E[Y] for any two variables (independent or not), this is called linearity of expectation.

"The average of the squares is the square of the average." Wrong, and it's the single most common slip with expectations. Take the weights above: E[X] = 3, so (E[X])² = 9, but E[X²] = 10. In general E[g(X)] ≠ g(E[X]) unless g is a straight line. You can even predict the direction for squares: E[X²] − (E[X])² turns out to be the average squared distance from the balance point, which can't be negative. So E[X²] ≥ (E[X])² always, with equality only when X never varies. Lesson 7 gives that gap its name, the variance. The same mistake in another costume: E[1/X] ≠ 1/E[X].

5 · Worked example: weights x/10

X takes the values 1, 2, 3, 4 with P(X = x) = x/10. (a) Check this is a mass function. (b) Find E[X]. (c) Find E[X²] and compare it with (E[X])². (d) Find E[3X + 2].

(a) Every value is positive, and (1 + 2 + 3 + 4)/10 = 10/10 = 1. Both checks from L5 pass.

(b) Multiply each value by its weight and add. Each term is x · x/10:

E[X] = (1 + 4 + 9 + 16)/10 = 30/10 = 3

Sanity check: 3 sits right of the middle, 2.5, because the heavier weights are on the right. (That's the beam you balanced.)

(c) Keep the weights, move each value to x². Each term is x² · x/10:

E[X²] = (1 + 8 + 27 + 64)/10 = 100/10 = 10

And (E[X])² = 3² = 9. They differ, by 1, in the direction the trap promised.

(d) Linearity: E[3X + 2] = 3 × 3 + 2 = 11. If you distrust it, do it the long way, with values 5, 8, 11, 14:

(5 + 16 + 33 + 56)/10 = 110/10 = 11

A continuous companion. Let f(x) = x/2 on (0, 2). It's a density: never negative, and its graph is a triangle of base 2 and height 1, area 1. Then

E[X] = ∫02 x · x/2 dx = [x³/6]02 = 8/6 = 4/3

Right of the middle, 1, because the sand piles up toward 2.

In one or two sentences of your own: why does a straight-line g carry the balance point along with it, while squaring pushes the balance point past g(E[X])?

Compare with a model answer

A straight line stretches every distance by the same factor and shifts everything by the same amount, so the pulls on each side still cancel at the moved point. Squaring stretches the large values much more than the small ones, so the right side gains extra pull and the balance moves right.

Your turn, half done. For the same density f(x) = x/2 on (0, 2), find E[X²] and compare it with (E[X])² = 16/9.

Step 1: keep the weights, move the values: E[X²] = ∫02 x² · x/2 dx. Step 2: the integrand is x³/2, whose antiderivative is ____ . Step 3: evaluate from 0 to 2 to get ____, and check it is bigger than 16/9.

Check your steps

The antiderivative is x⁴/8. From 0 to 2: 16/8 = 2. And 2 > 16/9 ≈ 1.78, as it must be: the average of the squares beats the square of the average.

Expectation is the hinge between probability and data. The law of large numbers (Unit I, later) says the average of many independent draws settles on E[X]; your corpus opens the topic with exactly that remark, and it's why the street game pays 3.5 a roll in the long run. Probability itself is an expectation: for the indicator of an event A (1 if A happens, 0 if not), E[indicator] = P(A). In estimation, "unbiased" means E[estimator] = true value; in machine learning, a model is trained to minimise an expected loss. The "average of a function isn't the function of the average" fact grows into Jensen's inequality: for any convex g, E[g(X)] ≥ g(E[X]). And measure theory writes all of this as one integral, ∫ X dP, which is how your corpus states its theorems on expectation.

Why this matters for you

EXAM  Expect: "find c, then find the mean" for a p.m.f. or p.d.f.; E[aX + b] from E[X]; E[X²] as a step toward the variance (next lesson); and true-or-false statements such as "E[X] always exists" (false: the Cauchy density has none), "E[1/X] = 1/E[X]" (false), "E[X + Y] = E[X] + E[Y] needs independence" (false). Nearly every named distribution you meet next is introduced with its mean.

Go deeper — one proof, one ISI problem (optional, ~15 min)

Prove it

Let X take only the values 0, 1, 2, 3, … Show that

E[X] = P(X ≥ 1) + P(X ≥ 2) + P(X ≥ 3) + …

It's called the tail-sum formula, and it often turns a hard sum into an easy one.

Worked proof

Write p(k) = P(X = k). The term k · p(k) is p(k) added k times. Stack those copies in a table: row 1 holds one copy of every p(k) with k ≥ 1, row 2 one copy of every p(k) with k ≥ 2, and so on. Then p(k) appears in rows 1, 2, …, k: exactly k times, as needed.

Adding row by row instead of column by column, row j is p(j) + p(j + 1) + … = P(X ≥ j). Every entry is non-negative, so the order of adding doesn't change the total. Hence

E[X] = Σk k p(k) = Σj ≥ 1 P(X ≥ j) ∎

Check on a die: P(X ≥ 1), …, P(X ≥ 6) are 6/6, 5/6, …, 1/6, which add to 21/6 = 3.5. ✓

Your corpus states it as Σk ≥ 0 P(X > k), the same sum with the index shifted by one.

An ISI entrance problem

From the ISI M.Stat 2017 descriptive paper (PSB), Q6: you've forgotten the code of a 4-digit combination lock. The true code was chosen uniformly at random from all 10,000. Find the expected number of attempts to open it if you (i) try 0000 to 9999 in order; (ii) pick each attempt at random from all codes, with replacement (repeats possible); (iii) pick at random without replacement (never repeating).

Worked solution

Write N = 10,000 and let T be the number of attempts.

(i) The true code is equally likely to be any of the N codes, so its place in the list 0000, 0001, … is equally likely to be 1, 2, …, N. Then E[T] = (1 + 2 + … + N)/N. Pair the first and last terms, the second and second-last, and so on: each pair sums to N + 1, and there are N/2 pairs, so the sum is N(N + 1)/2 and

E[T] = (N + 1)/2 = 5000.5

(ii) Each attempt hits with chance 1/N, independently of the others. "At least k attempts are needed" means the first k − 1 all missed, so P(T ≥ k) = (1 − 1/N)k−1 by the multiplication rule for independent events (L2). Now use the tail-sum formula you just proved, with r = 1 − 1/N:

E[T] = 1 + r + r² + … = 1/(1 − r) = N = 10,000

(The sum of 1 + r + r² + … for 0 ≤ r < 1 is 1/(1 − r): call it S; then S − rS = 1.)

(iii) Picking without replacement until every code is used just puts all N codes in a random order, every order equally likely. The true code is equally likely to sit in any of the N places: swapping place i with place j turns the orders with the code at i one-for-one into those with it at j, so each place gets the same share. So T is again equally likely to be 1, …, N, and E[T] = 5000.5, exactly as in (i).

The lesson in it: forgetting what you've tried costs you nearly double, 10,000 against 5000.5 attempts on average.

Checked by script (the ISI checks folder of the practice bank, file psb-2017-q6): 200,000 simulated locks gave means 4993.8, 10000.9 and 4995.9, each within 4 standard errors of 5000.5, 10,000 and 5000.5; an exact enumeration for N = 5 gave 3 = (N + 1)/2.
